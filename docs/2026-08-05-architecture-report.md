# 자취방 전월세 시세 대시보드 아키텍처 보고서

**작성일**: 2026년 8월 5일
**프로젝트**: Wabi Estate (청년들을 위한 부동산 자취 원룸 정보 웹 플랫폼)

---

## 1. 아키텍처 개요 (Overview)

본 프로젝트는 데이터 수집부터 최종 사용자 서빙까지 100% 무료 인프라(로컬 리소스 및 클라우드 무료 티어)를 기반으로 구축되었습니다. 대용량 데이터의 무거운 집계 작업은 로컬 환경에서 처리하고, 가벼운 결과물 서빙 및 UI 렌더링은 클라우드로 이관하여 운영 효율성과 비용 최적화를 모두 달성했습니다.

## 2. 백엔드 구조 및 내부 데이터 파이프라인 (Data Pipeline)

백엔드 파이프라인은 로컬 Docker 환경에서 완전히 자동화되어 동작합니다.

- **데이터 수집 (Collector)**: Node.js CLI 기반 워커가 국토부 공공데이터 API를 호출하여 raw 데이터를 수집합니다.
- **분석 저장소 (ClickHouse)**: 대용량 시계열 처리에 특화된 로컬 ClickHouse를 활용하여 `AggregatingMergeTree` 엔진과 Materialized View로 실시간에 가까운 고속 데이터 집계를 수행합니다.
- **서빙 저장소 (Supabase)**: 최종 집계가 완료된 월별 트렌드 및 지역 요약 데이터만을 클라우드 관계형 DB(Supabase)에 동기화(`Upsert`)합니다. Supabase는 RLS(Row Level Security)를 통해 익명 사용자에게 안전한 읽기 전용 접근을 제공합니다.
- **오케스트레이션 (Apache Airflow)**: 
  1. 매월 1일 수집(Collect) 작업 병렬 실행
  2. 완료 후 Supabase 데이터 동기화(Sync) 
  3. 완료 후 Vercel 서버의 ISR 캐시 무효화(Revalidate) 웹훅 호출
  의 순서로 데이터의 파이프라인 흐름을 완벽하게 자동화합니다.

## 3. 프론트엔드 구조 및 서버 API 파이프라인

초기에 검토되었던 Oracle VM + Caddy 기반의 복잡한 직접 연동을 덜어내고, 보안성과 유지보수성이 훨씬 뛰어난 **Next.js 15+ API & Supabase 연동 방식**으로 전환했습니다.

- **서버 컴포넌트 중심 아키텍처 (RSC)**: `app/page.tsx`, `app/regions/[code]/page.tsx` 등 메인 화면은 전부 서버 컴포넌트로 구축되었습니다. 클라이언트 브라우저로 전송되는 자바스크립트를 획기적으로 줄여 초깃값 로딩 속도를 향상했습니다.
- **API 클라이언트 브릿지 (`lib/api-client.ts`)**: 프론트엔드는 백엔드 파이프라인이 밀어넣은 Supabase 데이터를 서버 사이드에서 직접 조회합니다.
  - **안전한 Fallback(듀얼 로직)**: 로컬 개발 환경이거나 Supabase 연결이 실패할 경우, 시스템 장애를 일으키지 않고 UI 마크업 렌더링을 시연하기 위한 안전한 정적 Mock 데이터를 반환하도록 설계되었습니다.
- **웹훅 연동 (Revalidate API)**: Next.js API Routes(`/app/api/revalidate/route.ts`)를 열어두어 백엔드 Airflow가 데이터 동기화를 마친 직후 캐시를 갱신할 수 있는 파이프라인의 종단점(Endpoint) 역할을 합니다. 

## 4. 렌더링 방식 (Rendering Strategy)

성능 극대화와 SEO를 위해 **정적 생성(SSG)과 점진적 정적 재생성(ISR)을 결합**하였습니다.

- **SSG (`generateStaticParams`)**: 14개의 핵심 지역(서울 10개, 경기 4개) 상세 페이지를 빌드 타임에 완전히 정적으로 생성해 둡니다. 데이터베이스 쿼리를 실시간으로 실행하지 않으므로 Vercel CDN을 통해 지연 없는 즉각적인 렌더링을 제공합니다.
- **On-Demand ISR**: 페이지의 `revalidate` 옵션을 30일(2592000초)로 넉넉하게 설정하여 불필요한 재생성을 막고, 오직 백엔드 Airflow가 `/api/revalidate` 웹훅을 호출할 때만(월 1회 데이터 업데이트 시) 캐시를 새로고침하여 궁극의 속도와 데이터 최신성을 동시에 확보했습니다.

## 5. 결합 과정 및 결론 (Integration & Conclusion)

- 아키텍처 재설계를 통해 프론트엔드와 백엔드가 완전히 디커플링(Decoupling)되어, 어느 한쪽 서버가 재배포되더라도 서로의 시스템 안정성을 해치지 않는 마이크로서비스 형태를 갖추었습니다.
- 유기적이고 부드러운 Wabi-sabi 디자인 시스템(곡선형 카드, 이중 노이즈 텍스처, 자연스러운 애니메이션)이 컴포넌트 단위부터 레이아웃까지 빈틈없이 결합되었고, 결과적으로 시각적으로 훌륭하면서도 내부적으로는 가장 최신화된 파이프라인을 보유한 멋진 대시보드가 완성되었습니다.
