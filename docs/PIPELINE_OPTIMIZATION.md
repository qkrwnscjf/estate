# Data Pipeline Optimization & Troubleshooting

본 문서는 **Estate for Life** 프로젝트에서 국토교통부(MOLIT) 실거래가 데이터를 수집하고 가공하는 파이프라인을 최적화하며 겪은 트러블슈팅과 그 정량적인 해결 과정을 기록합니다.

## ⚠️ 1. 문제 정의 (Problem Definition)
초기 데이터 파이프라인 설계 시, 실거래가의 변동성을 실시간으로 반영하고자 **매일 1년 치의 데이터(Daily Batch)**를 수집하여 DB에 적재하는 방식을 고려했습니다. 

그러나 이 방식은 다음과 같은 치명적인 문제를 안고 있었습니다:
1. **API 호출 제한 및 네트워크 병목**: 전국 250개 시군구의 12개월 치 데이터를 매일 호출하면 하루 약 3,000번, **월 90,000번**의 무거운 네트워크 트래픽이 발생합니다.
2. **컴퓨팅 리소스 낭비**: 매일 누적된 수천만 건의 데이터를 Apache Spark 메모리에 올려 이상치를 제거하고 이동평균을 다시 계산하는 과정에서 심각한 클라우드 과금이 예상되었습니다.
3. **스토리지 낭비**: 단순 `INSERT`를 수행할 경우 매일 똑같은 과거 데이터가 중복으로 쌓여 데이터베이스(Supabase) 용량이 폭발적으로 증가합니다.

## 🔬 2. 원인 분석: 도메인 지식의 부재
국토교통부 실거래가 데이터의 본질적인 특성을 분석한 결과, 매일 전체 데이터를 긁어오는 것은 매우 비효율적이라는 사실을 발견했습니다.
- **30일 지연 등록 의무**: 부동산 법령상 실거래가는 '계약 체결일로부터 30일 이내 신고' 의무가 있습니다. 즉, 오늘 거래가 발생해도 전산망에는 한 달 뒤에야 등록될 수 있습니다.
- **정적인 데이터 성격**: 주식이나 코인과 달리 부동산 가격은 분 단위로 급변하지 않습니다.

## 🚀 3. 해결 방안 (Solution Architecture)
위의 도메인 분석을 바탕으로, 파이프라인 아키텍처를 전면 개편했습니다.

### A. 수집 범위 최소화 (최근 2개월 / Rolling Window)
- 전체 연도를 매일 조회하지 않고, 지연 신고 기간(30일)을 안전하게 커버할 수 있는 **최신 2개월 분량만 매일 수집**하도록 API 호출 범위를 좁혔습니다.

### B. 일일 배치 (Daily Batch) 복구
- 수집 범위를 획기적으로 줄였기 때문에, 사용자의 '최신 실거래가 확인' 니즈를 충족하기 위해 **파이프라인을 매일(Daily) 구동**해도 인프라에 전혀 부담이 가지 않습니다. 어제 새롭게 신고된 매물을 오늘 즉각 확인할 수 있게 되었습니다.

### C. 멱등성을 보장하는 UPSERT 전략
- Supabase 적재 시 `계약일 + 보증금 + 월세 + 주소`를 복합 고유 키(Composite Key)로 설정하여, **기존에 존재하는 거래 건은 무시/업데이트(UPSERT)** 하도록 처리했습니다.

## 📊 4. 정량적 최적화 성과 (Quantitative Insights)

파이프라인 최적화 전/후의 정량적 지표 변화는 다음과 같습니다.

| 지표 | 최적화 전 (AS-IS: 매일 1년치 조회) | 최적화 후 (TO-BE: 매일 최근 2개월만 조회) | 절감률 |
| :--- | :--- | :--- | :--- |
| **API 호출 횟수 (월간)** | 약 90,000 회 | 약 15,000 회 | **📉 83.3% 감소** |
| **Spark 처리 데이터량 (월간)** | 약 1,500만 건 | 약 250만 건 | **📉 83.3% 감소** |
| **DB 중복 적재 발생률** | 발생함 (지수 증가) | 0% (UPSERT) | **📉 100% 방어** |

## 💡 결론 (Conclusion)
단순히 데이터를 수집하고 화면에 띄우는 1차원적인 개발을 넘어, **'데이터 도메인(부동산 실거래가)의 특성'을 깊게 이해하고 이를 바탕으로 시스템 아키텍처를 최적화**했습니다. 결과적으로 클라우드 인프라 유지 비용과 API 부하를 80% 이상 획기적으로 절감하면서도, 사용자에게는 '가장 최신의 실거래가 트렌드'를 지연 없이 매일 실시간으로 제공할 수 있게 되었습니다.
